# 按需登录与手动接续

## 用户设置

「登录失效后自动重新登录」默认关闭。开启后，应用允许使用本机已保存的凭据，在原官网登录页面恢复会话；需要额外验证或不能完成验证时，将页面交给用户继续。

应用只在同步、打开官网或读取地址等用户操作中检查登录，不定时保活、不保存完整浏览器档案、不延长 Cookie 有效期。关闭主界面会退出应用。

## 恢复流程

1. 恢复目标卡的独立加密 Cookie，并通过只读信息接口核对卡号。
2. 确认会话失效且设置开启后，加载临时隐藏的原官网登录页面。
3. 由官网表单处理密码加密、验证码令牌和设备校验；本地模块只支持当前已适配的页面交互。
4. 每轮最多三次验证尝试、一次密码提交。不能确认成功、额外手机/邮箱验证或未知验证类型时，转入手动窗口。
5. 成功后再次核对卡号，保存真实有效期和范围的 Cookie，释放临时页面，继续同步。

同一卡的恢复请求复用同一个任务，跨卡登录依次处理。失败后有冷却时间；停用设置、取消任务或退出应用可停止恢复。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `electron/login-coordinator.ts` | 请求合并、跨卡串行、失败冷却和原因保留 |
| `electron/login-window.ts` | 隐藏执行、成功释放、原页面手动接续 |
| `electron/login-input.ts` | 当前页面的输入通道与资源释放 |
| `electron/auto-login.ts` | 官网控件就绪检查与登录结果核对 |
| `electron/session-vault.ts` | Cookie 校验、真实有效期、每卡捕获队列 |

官网页面没有 Node 权限或本地数据权限。敏感凭据不写入公开日志；Cookie 在进入 SQLite 前系统加密。

## 验证与限制

默认浏览器测试使用虚构页面，覆盖成功时保持隐藏、提交控件晚于验证结果就绪、失败后显示同一页面、停止和异常清理。

```sh
npm run test:login-browser
```

现场账户验证结果不用于推算长期成功率，也不公开账户统计。服务端可使会话失效，页面、控件或验证规则变化时仍可能需要用户手动登录。
