# 官网交易与确认边界

v0.6.2 负责本地规划、来源选择和打开官网。v0.7.0 新增[应用内扣卡兑换](native-checkout.md)：读取实时规格与地址、获取结算预览，用户明确确认后由主进程提交交易并核对结果。本地清单不会自动写入官网购物车。

## 为什么需要实时结算与明确确认

列表快照不足以代表实时交易条件。具体 SKU、库存、配送地区、运费、实名要求和额外验证可能在结算时变化；不同卡的余额与可兑换库存也不能混用。

提交路径使用模拟服务端测试；指定真实卡只验证到结算预览，测试模式下最终提交被硬性禁用。官网页面使用的内部接口没有公开稳定性保证，异常验证、支付或未知结构不按普通扣卡流程猜测处理。

## 如果将来扩展交易

需要先明确授权及接口合约，并验证以下条件：

- 始终使用目标卡的独立会话、库存分组和地址。
- 重新获取 SKU、价格、库存和配送结果，不能用本地缓存替代实时校验。
- 尊重官网风控、协议、手机/邮箱等额外验证。
- 明确订单幂等、超时后查询、重复提交和失败恢复行为。
- 单独覆盖真实交易验收及审计，不能把只读成功当成兑换成功。

## 地址新增

官网地址新增是独立确认操作：检查配送类型与地址参数，复用完全相同的既有地址，新增后只读查询核验。结果不明确时提示用户到官网核对，不盲目重试可能已成功的写入。

本地地址编辑、删除和默认选择不自动修改官网地址。公开测试仅使用模拟写入；真实账户的地址、配送统计和标识不保存在本文件。
