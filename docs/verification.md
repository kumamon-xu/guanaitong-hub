## 数据可靠性

`tests/database.test.ts` 使用临时目录和测试密钥，覆盖：

- 旧文件完整导入、成功标记、重复启动、损坏输入与修复后重试。
- 未知数值、外键、唯一约束、来源报价与清单关联。
- SQL 中途失败、错误系统密钥、加密失败、进程中断后的 WAL 恢复。
- 结构升级与失败回滚、较新版本拒绝、损坏数据库保持原样。
- v1/v2/v3 备份兼容、统一恢复、地址保留、Cookie 排除、历史记录恢复顺序。
- 订单筛选的中国日期边界、查询数量与业务快照一致。

## 查询与渲染规模

性能用例创建 **600 件合成商品**：每次查询只返回当前页，总览仅携带预览与清单需要的数据；总览传输大小低于完整快照的 1/20。通过禁止商品/报价写入的测试触发器，验证卡片备注和设置修改不会重写目录。

原生界面用例创建 **120 件合成商品**，检查分页、虚拟窗口 DOM 数量、筛选订单导出、标签与任务阶段。该检查验证数据访问规模和交互，不是对任意真实数据量的固定响应时间保证。

## 同步、诊断与发布

`tests/operations.test.ts` 覆盖并发上限、同卡请求复用、排队与运行中取消、失败后继续调度、官网错误分类、受控重试、IPC 注入拒绝、预算单位、CSV 公式中和、更新清单验证及签名凭据缺失时拒绝构建。

真实账户测试只能在账号持有者授权后执行，且以只读查询为主。常规单元与 CI 测试不会自动执行 `scripts/check-live.mjs`，也不会使用个人卡号或已保存的会话。
