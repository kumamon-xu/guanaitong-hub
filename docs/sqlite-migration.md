# 数据库迁移与恢复

当前程序使用 `vault/hub.sqlite`，无需数据库服务。结构版本为 v3，统一口令备份为 v3；同时兼容旧文件存储、v1/v2 `.gathub` 和 `.gataddr`。

## 首次导入旧文件

首次启动会备份旧 `state.json`、`addresses.enc` 和已知卡片的 `session-*.enc`，校验后在一个事务内导入卡片、商品、全部来源报价、订单、收藏、合并关系、清单、活动、设置、地址及会话。

- 旧文件不删除，副本位于应用数据目录的 `backups/legacy-*`。
- 数据、关联核对与成功标记一起提交，成功后不重复导入旧文件。
- 任何解密、校验或完整性失败都会停止迁移，修复后可重新启动。
- 初始化记录缺失且数据库已有内容时，拒绝用旧文件或空数据覆盖。

## 访问层与数据语义

`persistence.ts` 定义卡片、地址和会话接口。业务类保留校验，桌面程序统一注入 `SqliteRepository`；`legacy-storage.ts` 只用于兼容导入和测试。

| 表 | 内容 |
| --- | --- |
| `cards`、`products`、`offers` | 卡片、整合商品及每卡来源报价 |
| `orders`、`cart`、`manual_merges` | 历史订单、兑换计划和手动合并 |
| `addresses`、`activities`、`settings` | 本地地址、活动和偏好 |
| `sessions` | 系统加密的独立卡片会话 |
| `price_history`、`sync_tasks` | 报价历史与同步批次/进度 |
| `schema_migrations`、`storage_meta` | 结构版本和初始化记录 |

余额、价格、库存及订单金额允许 `NULL`。报价唯一定位到卡片和官网来源；外键防止无主关联。清单引用卡片和商品，允许报价消失后保留计划并提示失效。

系统加密在 SQL 写入前执行，自由文本载荷也加密。检索明文只放入 `TEMP` 内存表，不进入数据库/WAL。日常保存按键更新变化的行，使用 WAL、`synchronous=FULL` 和事务保证一致性。

## 统一备份

在「设置与备份」导出 `.gathub`，设置独立口令。v3 包含卡片凭据、商品、收藏、清单、订单、活动、设置、合并关系、地址、报价历史和同步记录；Cookie 不进入口令备份。

恢复先解密、校验并预览数量；确认后生成当前数据库安全副本，再事务替换。失败不覆盖当前完整数据。旧卡片备份保留当前地址簿，单独地址备份只替换地址；恢复卡片后重新官网登录。

## 结构升级

`database-migrations.ts` 只追加迁移，当前为 v1 核心表、v2 加密会话、v3 管理记录。已有库升级前用 `VACUUM INTO` 生成完整安全副本，再将脚本、`user_version` 和迁移记录一起提交；失败回滚未提交的改动。

不能直接复制运行中的 `.sqlite` 文件代替备份，因为已提交数据可能仍在 WAL 中。较新结构、迁移记录不一致或物理损坏时停止启动，并保留原文件。

## 手动恢复

1. 完全退出程序，复制整套 `vault` 到单独位置保存现场。
2. 在原设备及原系统用户下选择 `backups/before-schema-*.sqlite` 或 `before-restore-*.sqlite`。
3. 将当前 `hub.sqlite`、`hub.sqlite-wal`、`hub.sqlite-shm` 移到隔离目录，再把安全副本复制为 `hub.sqlite`。不要混用旧 WAL/SHM。
4. 使用支持该结构的软件启动。若需要口令恢复而损坏库无法启动，先保留整套旧目录，再启动空目录并恢复口令备份。

回退到旧文件存储版只能恢复旧文件快照，新版修改不会自动回写旧文件。新结构或新备份应使用支持它的版本处理。

系统加密绑定原设备和系统用户；换电脑必须使用口令备份。数据库、加密副本和口令备份都属于个人数据，不应上传 GitHub。
